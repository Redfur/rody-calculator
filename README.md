# Периоды родов

Калькулятор для акушера-гинеколога в виде PWA: врач вводит дату и время событий родов задним числом, по записям, и сразу видит продолжительность периодов, безводный промежуток и сроки профилактики эноксапарином. Результат можно скопировать.

Это один экран-калькулятор: ввести данные, посмотреть или скопировать результат, очистить. Протоколом или журналом приложение не является. Сервера, аккаунтов и аналитики нет. После первой загрузки приложение работает полностью офлайн, введённые данные хранятся только в `localStorage` на устройстве.

## Что считает

| Строка | Формула |
|---|---|
| Общая продолжительность родов | рождение плаценты − начало схваток |
| 1 период | начало потуг − начало схваток |
| 2 период | рождение плода − начало потуг |
| 3 период | рождение плаценты − рождение плода |
| Безводный промежуток | рождение плода − излитие вод |
| Продолжительность операции | конец − начало операции |
| 18 ч безводного периода | излитие вод + 18 ч (только момент, без предупреждений) |
| Эноксапарин | начало отсчёта + 10 и + 42 суток, с тем же временем |

Начало отсчёта для эноксапарина: конец операции, если операция добавлена и заполнена, иначе рождение плода + 12 ч. Сдвиги заданы константами в начале `src/calc.ts`.

Время считается как «настенное», без часового пояса (`Date.UTC(...) / 60000`), поэтому смена пояса или переход на летнее время не сдвигают результат.

Проверки:

- порядок событий `схватки ≤ потуги ≤ плод ≤ плацента`, `воды ≤ плод`, `начало операции < конец`;
- событие, нарушающее порядок, подсвечивается красным, связанные с ним периоды показывают «ошибка»;
- над итогами появляется подсказка. Если порядок восстанавливается сдвигом даты на день, подсказка об этом говорит. Обычно это забытое «›» после полуночи.

## Ввод

- Дата `дд.мм.гггг` и время `чч:мм` вводятся цифровой клавиатурой, точки и двоеточие подставляются сами.
- Когда время введено полностью, фокус переходит к следующему событию.
- Пустая дата берётся от ближайшего предыдущего события (если его нет, ставится сегодняшняя). Пока поле времени в фокусе, подставляемая дата видна приглушённо, а записывается в поле, когда введено время. После полуночи достаточно один раз нажать «›».

## Стек

React 18, TypeScript, Vite. Тесты на Vitest. Шрифты Golos Text и Unbounded (OFL) подключены локально из `src/fonts/`. Service worker собственный, без Workbox.

```
index.html                 точка входа Vite, мета-теги PWA и iOS
src/
  calc.ts                  чистые функции расчёта, проверок и форматирования (без DOM)
  calc.test.ts             тесты расчётов
  App.tsx                  экран: карточки, состояние, копирование, очистка
  components/EventFields.tsx  поля даты и времени с масками
  storage.ts               localStorage: { v: 1, fields, opOpen }
  useServiceWorkerUpdate.ts регистрация SW и плашка «Доступна новая версия»
  styles.css               токены цветов (светлая и тёмная тема), вёрстка
  fonts/                   woff2, подмножества cyrillic и latin
sw/sw.template.js          шаблон service worker
sw-plugin.ts               плагин Vite: собирает dist/sw.js со списком файлов и версией кэша
public/
  manifest.webmanifest
  icons/                   192, 512, maskable 512, apple-touch-icon 180
scripts/make-icons.py      генератор иконок (Pillow)
design/                    исходные макеты экрана
```

## Запуск локально

Нужен Node.js 20 или новее.

```bash
npm install
npm run dev        # дев-сервер с горячей перезагрузкой, http://localhost:5173
npm test           # тесты расчётов
npm run build      # проверка типов и сборка в dist/
npm run preview    # собранная версия, http://localhost:4173
```

В режиме `dev` service worker не регистрируется. Офлайн-режим и установку проверяйте на сборке: `npm run build && npm run preview`, либо раздайте `dist/` любым статическим сервером (например, `npx serve dist`). Service worker работает только на `localhost` или по HTTPS.

## Деплой на GitHub Pages

Все пути в сборке относительные (`base: './'`), поэтому сайт работает и в подпапке `https://<user>.github.io/<repo>/`.

1. В репозитории откройте **Settings → Pages** и в поле **Source** выберите **GitHub Actions**.
2. Сделайте push в `main`. Workflow `.github/workflows/deploy.yml` прогонит тесты, соберёт проект и опубликует `dist/`.
3. Откройте сайт на телефоне и добавьте его на домашний экран: в Safari через «Поделиться → На экран „Домой“», в Chrome через «Установить приложение».

Вручную: `npm run build` и выложить содержимое `dist/` на любой статический хостинг.

## Обновления и кэш

Service worker при установке кэширует все файлы сборки (стратегия cache-first). Имя кэша `rody-v1-<хеш сборки>` меняется автоматически при каждом изменении файлов, а старые кэши удаляются в `activate`. Новая версия активируется сразу (`skipWaiting` + `clients.claim`), и внизу экрана появляется плашка «Доступна новая версия — Обновить». Введённые данные при перезагрузке сохраняются.

Префикс `v1` нужно поднимать вручную только при несовместимых изменениях в логике самого service worker.
