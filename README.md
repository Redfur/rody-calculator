# Периоды родов

Калькулятор для акушера-гинеколога в виде PWA. Три вкладки:

- **Периоды.** Врач вводит дату и время событий родов задним числом, по записям, и сразу видит продолжительность периодов, безводный промежуток и сроки профилактики эноксапарином. Результат можно скопировать.
- **Партограмма.** Осмотры (раскрытие, головка, схватки) с графиком и подсказками по клиническим рекомендациям: слабость родовой деятельности, амниотомия, родостимуляция окситоцином, контрольные сроки.
- **Антибиотики.** Выбор препарата и времени первого введения, график введений и последнее введение для курсов 48 и 72 ч.

Сервера, аккаунтов и аналитики нет. После первой загрузки приложение работает полностью офлайн, введённые данные хранятся только в `localStorage` на устройстве. Кнопка «Очистить» (два нажатия) стирает все вкладки.

## Периоды

| Строка | Формула |
|---|---|
| Общая продолжительность родов | рождение плаценты − начало схваток |
| 1 период | начало потуг − начало схваток |
| 2 период | рождение плода − начало потуг |
| 3 период | рождение плаценты − рождение плода |
| Безводный промежуток | рождение плода − излитие вод |
| Продолжительность операции | конец − начало операции |
| 18 ч безводного периода | излитие вод + 18 ч (только момент, без предупреждений) |
| Эноксапарин | начало отсчёта + 10 и + 42 суток, с тем же временем |

Начало отсчёта для эноксапарина: конец операции, если операция добавлена и заполнена, иначе рождение плода + 12 ч. Сдвиги заданы константами в начале `src/calc.ts`.

Время считается как «настенное», без часового пояса (`Date.UTC(...) / 60000`), поэтому смена пояса или переход на летнее время не сдвигают результат.

Проверки:

- порядок событий `схватки ≤ потуги ≤ плод ≤ плацента`, `воды ≤ плод`, `начало операции < конец`;
- событие, нарушающее порядок, подсвечивается красным, связанные с ним периоды показывают «ошибка»;
- над итогами появляется подсказка. Если порядок восстанавливается сдвигом даты на день, подсказка об этом говорит. Обычно это забытое «›» после полуночи.

## Ввод

- Дата `дд.мм.гггг` и время `чч:мм` вводятся цифровой клавиатурой, точки и двоеточие подставляются сами.
- Тап по пустой дате сразу подставляет дату предыдущего события, а если его нет, сегодняшнюю. Дата выделена, так что другую можно сразу набрать поверх.
- Когда время введено полностью, фокус переходит к следующему событию. Пустая дата при этом берётся от предыдущего события. После полуночи достаточно один раз нажать «›».

## Партограмма

Начало регулярных схваток и излитие вод общие с вкладкой «Периоды». Рождение плода оттуда же закрывает второй период. Осмотр — это время (есть кнопка «Сейчас») и любые из значений: раскрытие 0–10 см, головка в пятых над лоном, число схваток за 10 минут и их продолжительность.

Подсказки строятся только из введённых данных. Все пороги — константы в начале `src/partogram.ts`.

| Подсказка | Условие | Источник |
|---|---|---|
| Первичная слабость, латентная фаза | от начала схваток до 5 см > 20 ч (первородящая) / > 14 ч (повторнородящая) | КР «Аномалии родовой деятельности», п. 2.2 |
| Первичная слабость, активная фаза | от 5 см до полного открытия > 8,6 ч / > 7,5 ч | там же, п. 2.2 |
| АРД по партограмме | одно и то же открытие держится ≥ 6 ч (5 см), 5 ч (6 см), 3 ч (7 см), 2,5 ч (8 см), 2 ч (9 см) | там же, п. 2.3 |
| Слабость активной фазы | ≥ 5 см, воды излились, нет динамики 4 ч | там же, п. 2.2 |
| Кесарево сечение | нет динамики > 4 ч при адекватных схватках (все подсчёты > 2 за 10 мин, не короче 20 с) или > 6 ч родостимуляции | там же, п. 3.2 |
| Слабые схватки | 2 и менее за 10 минут или короче 20 с | там же, п. 2.2 |
| Чрезмерно сильная деятельность / тахисистолия | > 5 схваток за 10 минут (в двух подсчётах подряд — тахисистолия) или схватка > 60 с | там же, п. 2.2, 3.1; КР «Нормальные роды» |
| Слабость во втором периоде | > 3 ч (4 ч с ЭА) у первородящей, > 2 ч (3 ч с ЭА) у повторнородящей | там же, п. 2.2 |
| Головка не продвигается | во втором периоде > 1 ч на одном уровне | там же, п. 2.2, 3.2 |
| Скорость раскрытия | в активной фазе < 0,5 см/ч | КР «Нормальные роды» |

При признаках слабости в первом периоде показывается тактика из п. 3.1: амниотомия перед родостимуляцией, если пузырь цел, и схема окситоцина (низкие дозы, старт 3 мЕД/мин, шаг каждые 20–30 мин до 4–5 схваток за 10 минут, 33 мЕД/мин — предельно опасный уровень). Для ещё не наступивших порогов выводятся контрольные сроки.

Подсказки — справка по тексту КР Минздрава России «Аномалии родовой деятельности» (2024) и «Нормальные роды» (2024). Решение принимает врач.

## Антибиотики

| Препарат | Доза | Интервал | Курсы |
|---|---|---|---|
| Цефазолин | 1 г | 8 ч | 48 и 72 ч |
| Амоксициллин + клавулановая кислота | 1,2 г | 8 ч | 48 и 72 ч |
| Ампициллин + сульбактам | 1,5 г | 6 ч | 48 и 72 ч |

Введения идут от первого с шагом интервала. Курс на N часов включает введения, начатые раньше, чем через N часов от первого. Пример: первое введение 13.10 в 01:00, каждые 6 ч, курс 48 ч — последнее (8-е) 14.10 в 19:00. Список препаратов, доз и курсов — таблица `ANTIBIOTICS` в `src/antibiotics.ts`.

## Стек

React 18, TypeScript, Vite. Тесты на Vitest. Шрифты Golos Text и Unbounded (OFL) подключены локально из `src/fonts/`. Service worker собственный, без Workbox.

  partogram.ts             партограмма: фазы, пороги КР, подсказки (без DOM)
  antibiotics.ts           антибиотики: препараты и график введений (без DOM)
  *.test.ts                тесты расчётов

  screens/                 вкладки «Периоды», «Партограмма», «Антибиотики»

  storage.ts               localStorage: { v: 2, tab, fields, opOpen, abx, parto }, перенос со схемы v1
  useServiceWorkerUpdate.ts регистрация SW и плашка «Доступна новая версия»

## Запуск локально

Нужен Node.js 20 или новее.

```bash
npm install
npm run dev        # дев-сервер с горячей перезагрузкой, http://localhost:5173
npm test           # тесты расчётов, партограммы и антибиотиков
npm run build      # проверка типов и сборка в dist/
npm run preview    # собранная версия, http://localhost:4173
```

В режиме `dev` service worker не регистрируется. Офлайн-режим и установку проверяйте на сборке: `npm run build && npm run preview`, либо раздайте `dist/` любым статическим сервером (например, `npx serve dist`). Service worker работает только на `localhost` или по HTTPS.

## Деплой на GitHub Pages

Все пути в сборке относительные (`base: './'`), поэтому сайт работает и в подпапке `https://<user>.github.io/<repo>/`.

1. В репозитории откройте **Settings → Pages** и в поле **Source** выберите **GitHub Actions**.
2. Сделайте push в `main`. Workflow `.github/workflows/deploy.yml` прогонит тесты, соберёт проект и опубликует `dist/`.
3. Откройте сайт на телефоне и добавьте его на домашний экран: в Safari через «Поделиться → На экран „Домой“», в Chrome через «Установить приложение».

Вручную: `npm run build` и выложить содержимое `dist/` на любой статический хостинг.

## Обновления и кэш

Service worker при установке кэширует все файлы сборки (стратегия cache-first). Имя кэша `rody-v1-<хеш сборки>` меняется автоматически при каждом изменении файлов, а старые кэши удаляются в `activate`. Новая версия активируется сразу (`skipWaiting` + `clients.claim`), и внизу экрана появляется плашка «Доступна новая версия — Обновить». Введённые данные при перезагрузке сохраняются.

Префикс `v1` нужно поднимать вручную только при несовместимых изменениях в логике самого service worker.
